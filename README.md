# Couch

A warm, voice-first iOS 26 app for psychology students to practise simulated therapy sessions and walk away with structured feedback. **Practice therapy before it counts.**

## What's in V1

- Onboarding flow: name → privacy consent → social proof → stressors → goals → quick profile → science explainer → personalising loader → scenario recommendation → scenario detail → notifications → microphone
- One launch scenario — **Marcus**, a 28-year-old in his first session — backed by a LiveKit-dispatched voice agent with an optional LemonSlice avatar
- Voice-first session via LiveKit by default, with local text input support and a legacy direct-to-ElevenLabs fallback when the backend transport is disabled or unavailable
- Freeze-recovery prompts to help users when they go blank
- Mandatory non-dismissable debrief: 3 strengths · 3 next moves · 1 micro-drill · confidence checkpoint, generated by OpenAI's Responses API with strict structured output
- Post-onboarding tab shell with Home, History, and Settings plus a floating quick-rep accessory
- A one-time post-debrief "aha moment" card that mirrors the user's stated friction back with it removed
- Local-only persistence via SwiftData — no accounts, no on-device transcripts leaving the device

## Architecture

```
Couch/
  App/                 entry + AppRoot routing
  Branding/            warm Liquid Glass palette + glass card style + haptics
  Components/          shared cards, buttons, charts, portrait stage, and avatar rendering
  Models/              SwiftData @Model classes (UserProfile, Scenario, Session, Turn, Debrief, MicroDrill, StreakEvent)
  Persistence/         ModelContainer + first-launch seed data + TranscriptStore actor
  Scenarios/           static catalog (Marcus blueprint)
  Services/            OpenAIClient, DebriefService, MicPermissionService,
                       KeychainService, SecretsProvider, RapportEstimator,
                       AppFeatureFlags, ElevenLabsClient
  Services/Session/    ConversationDriver protocol + LiveKitConversationDriver
                       + LiveKitTokenClient + ElevenLabsConversationDriver
  Features/
    Onboarding/        OnboardingState + 12-step NavigationStack flow + permission handoff
    Session/           SessionContainer + SessionCoordinator + ConversationView + Transcript + FreezeHelpSheet
    Debrief/           DebriefCoordinator + non-dismissable DebriefGateFlow
    Home/              RootTabView + dashboard + quick-rep accessory
    History/           confidence trend + session history cards
    Settings/          practice defaults + notification toggle + local data reset
  Utilities/           OSLog categories + time formatting
backend/               Node.js LiveKit token server + LiveKit agent with
                       LemonSlice virtual avatar (see backend/README.md and
                       docs/avatar-architecture.md)
```

Concurrency posture: coordinators are `@MainActor @Observable`, network and disk services are actors / `@ModelActor`, and only `Sendable` value types ever cross isolation boundaries (mostly through `PersistentIdentifier`).

## Core workflows

### Launch and onboarding

- `AppRoot` ensures there is always a singleton `UserProfile` in SwiftData, then routes to `OnboardingFlow` until `onboardedAt` is set.
- `OnboardingState` keeps answers in memory during the flow and only persists them when the microphone step completes.
- The notifications step is skippable. The microphone step is not: it always resolves to a session mode.
- If iOS microphone permission is denied, the app intentionally falls back to `.text` mode and still completes onboarding.
- The personalising step calls back into `SeedData` so the Marcus scenario and micro-drill catalog exist before the user lands in the home shell.

### Session lifecycle

Codepaths: `Couch/Features/Session/SessionContainer.swift`, `Couch/Features/Session/ConversationView.swift`, `Couch/Features/Session/SessionCoordinator.swift`, `Couch/Services/Session/LiveKitConversationDriver.swift`, `Couch/Services/Session/LiveKitTokenClient.swift`, `Couch/Services/Session/ElevenLabsConversationDriver.swift`, `Couch/Persistence/TranscriptStore.swift`

1. `SessionContainer` shows a session intro screen first, then `ConversationView` creates a `SessionCoordinator` on first appearance after the user taps Start.
2. `SessionCoordinator` resolves the transport once per session: prefer `Scenario.transport` when `COUCH_LIVEKIT_ENABLED` is on, but fall back to the legacy direct path if the backend client is not configured.
3. `SessionCoordinator.startConnection()` inserts a `Session` row into SwiftData before opening the live conversation.
4. In the preferred path, `LiveKitTokenClient` posts `scenarioId`, `mode`, and a stable participant identity to `POST /v1/sessions/token`; `LiveKitConversationDriver` then joins the room, enables the microphone only for voice mode, and subscribes to remote avatar video when available.
5. If the backend transport is disabled or unavailable, `ElevenLabsConversationDriver` starts a public-agent conversation using `scenario.elevenLabsAgentId`; voice vs text is controlled with `ConversationOverrides(textOnly:)`.
6. Driver events are mapped into SwiftUI state:
   - conversation state -> `phase` (`intro`, `connecting`, `live`, `ending`, `ended`, `error`)
   - agent state -> `agentMode` (`idle`, `listening`, `speaking`)
   - message or transcription stream -> visible transcript turns
   - avatar availability -> static portrait vs live video hinting
7. Each new turn is appended to the on-screen transcript and persisted off the main actor through `TranscriptStore`.
8. Ending a session marks the `Session` as completed, stores the final rapport score, and presents the debrief gate.

Constraints to know:

- Freeze-help prompts are local-only `system` turns. They appear in the student's transcript UI but are not sent back to the Marcus agent.
- Missing `MARCUS_AGENT_ID` is a hard failure only for the legacy direct transport.
- LiveKit sessions require both `COUCH_BACKEND_URL` and `COUCH_BACKEND_SHARED_SECRET` on-device.
- Text mode is a first-class fallback, not a degraded error path.

### Home shell and post-rep loop

Codepaths: `Couch/Features/Home/RootTabView.swift`, `Couch/Features/Home/HomeView.swift`, `Couch/Features/History/HistoryView.swift`, `Couch/Features/Settings/SettingsView.swift`

- `RootTabView` presents three tabs: `HomeView`, `HistoryView`, and `SettingsView`.
- The floating quick-rep accessory always launches `SessionContainer` for the primary seeded scenario.
- `HomeView` computes weekly completions, streak length, and average confidence from SwiftData sessions and streak events.
- `HistoryView` filters completed sessions over 7-day, 30-day, or all-time windows and derives trend metrics from saved `Debrief.confidenceAfter` values.
- `SettingsView` persists weekly rep goal, default session mode, notification preference, and supports a destructive local-only reset of sessions, streaks, and profile answers.

### Debrief lifecycle

Codepaths: `Couch/Features/Debrief/DebriefGateFlow.swift`, `Couch/Features/Debrief/DebriefCoordinator.swift`, `Couch/Services/DebriefService.swift`, `Couch/Services/OpenAIClient.swift`

1. `DebriefGateFlow` is presented full-screen and uses `interactiveDismissDisabled(true)` so the user cannot skip the post-session feedback flow.
2. `DebriefCoordinator.generate()` renders the session snapshot into a transcript prompt and asks `DebriefService` for structured output.
3. `DebriefService` calls the OpenAI Responses API with a strict JSON Schema named `couch_debrief`.
4. The required payload shape is:
   - `strengths`: exactly 3 strings
   - `next_moves`: exactly 3 strings
   - `micro_drill`: `{ title, body }`
   - `notes`: optional-style context string, still required by schema
   - `risk_flags`: array of strings
5. Once decoded, the app persists a `Debrief`, links it to the `Session`, and inserts a `StreakEvent` only if one does not already exist for the current calendar day.
6. The user then steps through strengths -> next moves -> micro-drill -> confidence checkpoint -> completion.

Important constraints:

- The current implementation stores `confidenceAfter` when the user finishes the checkpoint. `confidenceBefore` exists on the model but is not currently populated anywhere in the flow.
- If debrief generation fails, the user can retry or exit back home from the error view.

### Secrets and trust boundaries

Codepaths: `Couch/Services/SecretsProvider.swift`, `Couch/Services/KeychainService.swift`

- `SecretsProvider` is the only app surface that reads raw secret values.
- Resolution order is:
  1. scheme / process environment
  2. bundled `Secrets.plist`
  3. `Info.plist` values
- `OPENAI_API_KEY` is additionally cached to the Keychain on first successful read, and later launches prefer the Keychain copy.
- `ELEVENLABS_API_KEY` is optional in the current V1 flow because the app connects to a public Marcus agent with `MARCUS_AGENT_ID` alone.
- This setup is acceptable for local development and TestFlight, but it is not appropriate for a production App Store build without moving API access behind a backend.

## Local setup

### 1. Open the project

```sh
open Couch.xcodeproj
```

Xcode will resolve SPM dependencies (ElevenLabs, LiveKit, swift-protobuf, etc.) on first open. The ElevenLabs SDK is pinned to `2.0.0+`.

### 2. Configure secrets

Copy `Couch/Secrets.plist.example` to `Couch/Secrets.plist` (gitignored) and fill in:

| Key | Where to get it |
|-----|-----------------|
| `OPENAI_API_KEY` | <https://platform.openai.com/api-keys> — used for the post-session debrief |
| `ELEVENLABS_API_KEY` | Optional for the legacy transport. Only needed if you switch away from the current **public** Marcus agent flow and start minting private-agent conversation tokens. |
| `MARCUS_AGENT_ID` | The agent ID from <https://elevenlabs.io/app/conversational-ai> for the Marcus persona (set as a **public** agent so the app can connect without a backend). Used only by the legacy direct transport. |
| `COUCH_LIVEKIT_ENABLED` | `YES` to switch the app to the LiveKit transport (see [`backend/README.md`](backend/README.md)). Defaults off so legacy builds still work. |
| `COUCH_AVATARS_ENABLED` | `YES` to render the live LemonSlice avatar on top of the static stage. |
| `COUCH_BACKEND_URL` | Base URL of your Couch backend (e.g. `http://localhost:8787` for local dev). Required when the LiveKit transport is on. |
| `COUCH_BACKEND_SHARED_SECRET` | Matches `COUCH_API_SHARED_SECRET` on the server and is sent as `X-Couch-Auth` on every token request. |

Then add `Couch/Secrets.plist` to the **Couch** app target in Xcode (drag into the Project Navigator and tick the Couch target). The app reads it at launch via `SecretsProvider`, with a Keychain fallback for the OpenAI key.

Alternatively, define `OPENAI_API_KEY`, `ELEVENLABS_API_KEY`, and `MARCUS_AGENT_ID` as scheme environment variables for ad-hoc local runs.
If you are using the preferred LiveKit transport, also provide `COUCH_LIVEKIT_ENABLED`, `COUCH_AVATARS_ENABLED`, `COUCH_BACKEND_URL`, and `COUCH_BACKEND_SHARED_SECRET`.

> **V1 only.** Storing the OpenAI key on-device is fine for dev and TestFlight but **not** for App Store distribution. The preferred session transport moves live session auth behind the backend, but the debrief flow still calls OpenAI directly from the app. The legacy ElevenLabs integration uses a public agent ID, not an ElevenLabs API key. `ElevenLabsClient` remains the seam for introducing signed-URL or private-agent auth later without rewriting the session views.

### 3. Configure the session transport

- **Preferred LiveKit + LemonSlice transport**: bring up the Node backend in [`backend/`](backend/). [`backend/README.md`](backend/README.md) covers env vars, token minting, local runs, and troubleshooting; [`docs/avatar-architecture.md`](docs/avatar-architecture.md) covers the system design.
- **Legacy direct transport**: use the system prompt from [`docs/couch_persona_sys_prompt.md`](docs/couch_persona_sys_prompt.md) and set the ElevenLabs agent to **public** so the app can connect using the agent ID alone.

### 4. Build and run

```sh
xcodebuild -project Couch.xcodeproj -scheme Couch -destination 'generic/platform=iOS Simulator' build
```

Or just hit ⌘R in Xcode against any iOS 26.2 simulator.

### 5. Tests

List available simulators first:

```sh
xcrun simctl list devices available
```

Then run Swift Testing unit tests + XCTest UI smoke tests with an available iPhone simulator:

```sh
xcodebuild -project Couch.xcodeproj -scheme Couch \
  -destination 'platform=iOS Simulator,name=<available iPhone simulator>' test
```

## Troubleshooting

### "Missing ElevenLabs agent ID"

- Cause: `MARCUS_AGENT_ID` is absent from the scheme environment and from `Couch/Secrets.plist`.
- Effect: `ElevenLabsClient.startConversation()` throws before the legacy direct session becomes live.
- Fix: add the public Marcus agent ID, then rebuild the app target so the value is visible at launch. If you intend to run the preferred backend flow, make sure the app is actually on the LiveKit transport instead of the legacy one.

### "Missing OpenAI API key" or debrief generation fails immediately

- Cause: `OPENAI_API_KEY` is missing, empty, or not attached to the Couch target.
- Effect: the session can run, but the debrief gate lands in its retry/error state.
- Fix: add the key to `Couch/Secrets.plist` or the scheme environment. If you recently changed plist values, clean/build so the updated bundle is used.

### Microphone prompt never appears or the app lands in text mode

- Cause: iOS has already resolved microphone permission for the app.
- Effect: onboarding either proceeds directly in voice mode (`granted`) or intentionally falls back to text mode (`denied`).
- Fix: reset simulator permissions if you need to re-test the prompt. Text mode fallback is expected behavior, not a bug.

### "Couch backend URL or shared secret is missing"

- Cause: `COUCH_LIVEKIT_ENABLED` is on, but the app cannot resolve `COUCH_BACKEND_URL` and/or `COUCH_BACKEND_SHARED_SECRET`.
- Effect: `SessionCoordinator` falls back to the legacy direct transport for new sessions.
- Fix: add both keys to `Couch/Secrets.plist` or the scheme environment, then relaunch the app. See [`backend/README.md`](backend/README.md) for the matching server configuration.

### Session connects but never shows live video

- Cause: avatar support is disabled or not fully configured on the backend.
- Effect: the session still runs, but `AvatarStageView` keeps the static portrait visible and may show the audio-only hint.
- Fix: verify `COUCH_AVATARS_ENABLED`, `COUCH_AVATAR_PROVIDER`, `LEMONSLICE_API_KEY`, and either `MARCUS_LEMONSLICE_AGENT_ID` or `MARCUS_LEMONSLICE_IMAGE_URL` in the backend env.

### Scenario or micro-drill data looks missing in previews/tests

- Cause: the preview/test container was created without seed data.
- Effect: home and session entry points may not find the Marcus scenario or drill catalog.
- Fix: use `AppModelContainer.previewContainer(seeded: true)` or call `SeedData.runIfNeeded(container:)` / `SeedData.ensureScenariosExist(in:)` before exercising those surfaces.
