# User Interface Wiki — Couch Audit

Audit of the Couch iOS SwiftUI app against the [raphaelsalaja/userinterface-wiki](https://github.com/raphaelsalaja/userinterface-wiki) skill (152 rules, 12 categories). The skill is written for web stacks (Next.js / React / CSS Modules / Framer Motion / View Transitions API / Web Audio), so this audit covers only the subset of rules that translate to SwiftUI and records the rest as **N/A (web-only)**.

- Skill version: 3.0.0 (installed at `~/.agents/skills/userinterface-wiki/`)
- Audit date: 2026-04-18
- Target branch state: working-tree at audit time (includes FloatingBackButton, PieSpinner, and modified onboarding/session views)
- Method: rule-by-rule pass over `Couch/` with `rg` + manual read of design-token, component, and flow files
- **No source files were modified as part of this audit.**

## 5. Audio Feedback (MEDIUM) — **N/A (app has no sound)**

Couch uses [Haptics.swift](Couch/Branding/Haptics.swift) only. No sounds are played. All `a11y-`*, `appropriate-*`, `impl-*`, `weight-*` audio rules are skipped.

**Side note (not from this rule set):** [Haptics.swift](Couch/Branding/Haptics.swift) centralizes haptic feedback (good hygiene). Haptic firing is placed *before* the action in [PrimaryButton.swift:14](Couch/Components/PrimaryButton.swift), [PillOption.swift:11](Couch/Components/PillOption.swift), [FloatingBackButton.swift:12](Couch/Components/FloatingBackButton.swift), and inline buttons in [HomeView.swift](Couch/Features/Home/HomeView.swift) — consistent with "confirmation feedback on commit".

## Appendix B — How to read a rule

The installed skill lives at `~/.agents/skills/userinterface-wiki/`. Each rule ID has a dedicated file under `rules/`, for example:

```
~/.agents/skills/userinterface-wiki/rules/timing-under-300ms.md
~/.agents/skills/userinterface-wiki/rules/physics-active-state.md
~/.agents/skills/userinterface-wiki/rules/ux-doherty-under-400ms.md
~/.agents/skills/userinterface-wiki/rules/visual-concentric-radius.md
```

When implementing a fix, read the rule file for the rationale and canonical examples (in web terms), then translate to the SwiftUI equivalent using this document's "SwiftUI mapping / proposal" column.
